# R01 — Governed retrieval contracts and infrastructure audit

The owner approved B179 on 2026-11-26 for #1028 and ADR-016 (#1025). A transfer grant matches the site, data classification and destination. The same grant covers every model operation for that combination.

## Authorization boundary

At query time, authorize the principal against current PostgreSQL row, field and revision data. At indexing time, check the site's index grant for each field. For external indexing require both that grant and a transfer grant for the index destination. For model calls resolve the site and operation through the shared AI provider resolver, then authorize the actual destination and every component before constructing the outbound request. Bind destination IDs to deployment-controlled endpoints; reauthorize any change. Resolution failure, an unknown classification, or a missing grant stops dispatch. Derive classifications from trusted metadata, including sensitive query text, encrypted fields and credentials. A component with multiple classifications requires all applicable grants.

The public contract in `@lumibase/contracts/platform` separates transfer grants from operation-based provider resolution. The resolver returns a model, provider, destination and opaque credential reference. Adapters retrieve secrets only after authorization. Grant matching makes no network requests. R03 integrates the index checks and R04 integrates the resolver and outbound checks. Existing generation paths and background jobs must adopt the shared boundary before claiming B179 coverage. Setup impact for R01 is n/a; the contract adds no installation setting.

## Observations an unauthorized row can change

| Observable | R03 paired-corpus check |
| --- | --- |
| Rank and score | Keep readable rows fixed. Add hidden high-scoring rows and hidden fields. Compare visible IDs, ordering and every exposed score. |
| Count and short results | Insert enough hidden matches to exhaust the candidate window. Compare counts, page lengths and pagination metadata, including no-answer cases. |
| Timing | Interleave repeated requests against both corpora under the same workload and cache conditions. Compare distributions using the tolerance registered before evaluation. |

Run these checks across sites, after revocation and while reindexing. Prefilter authorization or use a permission-scoped source query if the index cannot express the rule. Record any residual signal, affected principals and owner decision before rollout.
