# BT01 — Versioned JSON template contract and validation

**Parent:** #900 · **Task:** BT01 · **Owner lane:** Contracts

**Depends on:** none

**Codebase mirror:** [.kiro/specs/backend-templates/work-items/BT01.md](https://github.com/khuepm/LumiBase/blob/feature/backend-templates-spec/.kiro/specs/backend-templates/work-items/BT01.md)

## Outcome and scope
Define lumibase.template@v1 envelope embedding lumibase.config@v1; immutable templateVersion, slug, compatibility and optional named seed packs. Validate unknown versions, duplicate keys, dangling relations, unsupported field/storage features, size/depth/count limits and reserved/system resources. Canonical digest excludes transport metadata; source and target site IDs never enter portable artifacts. JSON Schema and Zod must agree.


## Implementation work breakdown
- [ ] BT01-W1: Add shared envelope/subschemas and generated MCP JSON Schema; reuse ConfigManifest rather than accepting a second field vocabulary.
- [ ] BT01-W2: Implement semantic validation in separate pure helpers: reserved resources, storage compatibility, relation graph, seed graph and bounds.
- [ ] BT01-W3: Implement canonical serialization/digest and fixtures for valid, invalid, reordered and schema-only manifests.

## Expected code touchpoints
packages/contracts/src/schemas/ (new template contract), config-manifest.ts integration; pure validation tests. These are planning boundaries, not exclusive file grants; coordinate shared changes and preserve unrelated work.

## Detailed acceptance criteria
### BT01-AC01 — Schema-only round trip

- [ ] Given a valid artifact with seedPacks omitted, validate/export/reparse it; normalized schema is equal and no seed default is inserted.
- Verification/evidence: Contract unit + property tests; attach test name, exact command, commit SHA and actual result.

### BT01-AC02 — Stable digest

- [ ] Reorder object keys and semantically unordered collections/fields; digest stays equal. Change a field or seed value; digest changes. Preserve order where meaningful.
- Verification/evidence: Property tests; attach test name, exact command, commit SHA and actual result.

### BT01-AC03 — Precise rejection

- [ ] Unknown format, invalid SemVer, duplicate collection/field/key, dangling relation and reserved system collection each return a stable error with JSON path; no service write is called.
- Verification/evidence: Table-driven negative tests; attach test name, exact command, commit SHA and actual result.

### BT01-AC04 — Limits

- [ ] Exercise exact boundary and boundary+1 for 2 MiB document, depth 32, 100 collections, 2000 fields, 500 relations, 1000 seed records and 1 MiB seed values; oversize fails before persistence.
- Verification/evidence: Boundary tests; limits exclude transport bytes; attach test name, exact command, commit SHA and actual result.

### BT01-AC05 — Portable identity

- [ ] Reject embedded source site IDs, runtime record IDs, executable SQL/code and secret-bearing unsupported sections; export contains no runtime identity.
- Verification/evidence: Negative fixtures; attach test name, exact command, commit SHA and actual result.

### BT01-AC06 — Schema fidelity

- [ ] Validate the same valid/invalid fixtures using Zod and generated JSON Schema; outcomes agree, including nullable references and optional seed packs.
- Verification/evidence: Contract parity test; attach test name, exact command, commit SHA and actual result.
