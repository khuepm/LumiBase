# BT05 — Optional seed packs with local references and permission-aware writes

**Parent:** #900 · **Task:** BT05 · **Owner lane:** Backend/data
**Spec:** `.kiro/specs/backend-templates/` · **Requirements:** R7
**Depends on:** BT01, BT04

**Status:** planning only; unassigned; no implementation started. v1 implementation scope.
**Codebase mirror:** [.kiro/specs/backend-templates/work-items/BT05.md](https://github.com/khuepm/LumiBase/blob/feature/backend-templates-spec/.kiro/specs/backend-templates/work-items/BT05.md)

## Outcome and scope
Default seedMode=none. Implement selected inline seed pack only, bounded for atomic v1. Allocate fresh domain IDs for logical record keys, resolve relation references in two passes and validate cycles/required constraints before writes. Use ItemService with caller context and transaction; suppress external side effects until commit. No passwords, users, credentials, binary files or arbitrary URL fetch. Later API/MCP item creation remains ordinary content operations.


## Implementation work breakdown
- [ ] BT05-W1: Define seedMode none|pack with explicit pack name; default none at every transport boundary.
- [ ] BT05-W2: Allocate logical-key mapping, validate reference graph and write via transaction-bound ItemService with caller context.
- [ ] BT05-W3: Enforce bounds and explicit cycle policy; no file downloads or raw DB bypass; integrate post-commit side effects with BT04.

## Expected code touchpoints
new seed resolver; ItemService transaction/context integration; shared seed contracts. These are planning boundaries, not exclusive file grants; coordinate shared changes and preserve unrelated work.

## Detailed acceptance criteria
### BT05-AC01 — No-seed default

- [ ] Install with argument omitted and with seedMode=none; every template collection exists and all content/junction counts are zero even if demo pack exists.
- Verification/evidence: DB tests; attach test name, exact command, commit SHA and actual result.

### BT05-AC02 — Pack selection

- [ ] Select demo; only its records are inserted. Unknown pack or contradictory none+pack input fails validation before schema writes.
- Verification/evidence: Contract + DB; attach test name, exact command, commit SHA and actual result.

### BT05-AC03 — Fresh identities

- [ ] Install same pack into A and B; record IDs differ, all references resolve within their target site and no source IDs remain.
- Verification/evidence: Two-site integration; attach test name, exact command, commit SHA and actual result.

### BT05-AC04 — Bad graph

- [ ] Duplicate logical key, missing target, incompatible collection and unsupported required cycle each fail with record/field path and no partial install.
- Verification/evidence: Graph negative matrix; attach test name, exact command, commit SHA and actual result.

### BT05-AC05 — Permissions

- [ ] Deny item:create for one seeded collection; whole install fails, with no partial schema/content or bypass of ItemService validation.
- Verification/evidence: Permission integration; attach test name, exact command, commit SHA and actual result.

### BT05-AC06 — Later population

- [ ] After no-seed install, create author/post and relation through REST and MCP; both read back in target site, inaccessible from unauthorized other site.
- Verification/evidence: API/MCP integration; attach test name, exact command, commit SHA and actual result.

### BT05-AC07 — Retry

- [ ] Repeat completed seeded install; counts and logical-key mappings do not change; content modified by the user is not reseeded.
- Verification/evidence: DB retry test; attach test name, exact command, commit SHA and actual result.
