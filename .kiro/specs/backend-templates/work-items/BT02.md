**Codebase mirror:** [.kiro/specs/backend-templates/work-items/BT02.md](https://github.com/khuepm/LumiBase/blob/feature/backend-templates-spec/.kiro/specs/backend-templates/work-items/BT02.md)

## Outcome and scope
Add private site-scoped templates and immutable revisions; bundled official templates are read-only global code assets, never shared tenant rows. Support create from JSON, edit draft, publish revision, list/get/export and capture selected schema from a source site. Capture defaults to schema-only; optional seed capture requires item read permission and redaction. No public marketplace in v1.


## Implementation work breakdown
- [ ] BT02-W1: Add template/draft/revision persistence with site-scoped uniqueness, migration and RLS pair; bundled catalog stays read-only.
- [ ] BT02-W2: Implement create/edit with optimistic draft revision checks, validate/publish, paginated list/get/export and schema capture.
- [ ] BT02-W3: Capture explicit collection closure; fail with missing dependency inventory rather than silently capturing extra tenant data; seed capture is explicit and permission-filtered.

## Expected code touchpoints
packages/database/src/schema/ + idempotent migrations/RLS; new catalog service/routes; config-export-service.ts integration. These are planning boundaries, not exclusive file grants; coordinate shared changes and preserve unrelated work.

## Detailed acceptance criteria
### BT02-AC01 — Draft authoring

- [ ] Create a schema-only draft on A, edit label with matching revision, publish 1.0.0, fetch/export it; target schema and content counts remain unchanged.
- Verification/evidence: Service integration; attach test name, exact command, commit SHA and actual result.

### BT02-AC02 — Concurrent edit

- [ ] Two edits use the same draft revision; exactly one succeeds and the other returns conflict without lost updates.
- Verification/evidence: Concurrent DB test; attach test name, exact command, commit SHA and actual result.

### BT02-AC03 — Immutable publication

- [ ] Attempt different content under the same site/slug/version; reject. Identical publication retry returns the existing revision, not a duplicate.
- Verification/evidence: DB uniqueness + API tests; attach test name, exact command, commit SHA and actual result.

### BT02-AC04 — Tenant boundary

- [ ] Principal with access only to B cannot list/get/capture A's private templates by guessed ID, slug or pagination; non-superuser RLS proves isolation.
- Verification/evidence: RBAC + real RLS tests; attach test name, exact command, commit SHA and actual result.

### BT02-AC05 — Capture fidelity

- [ ] Capture selected schema with all dependencies, export and reparse; fields/options/relations match. Missing dependent collection yields explicit preflight error.
- Verification/evidence: Round-trip test; attach test name, exact command, commit SHA and actual result.

### BT02-AC06 — Seed privacy

- [ ] Default capture reads no items; explicit capture checks each collection/record permission and excludes credentials/system users; denied capture publishes nothing.
- Verification/evidence: Permission tests; attach test name, exact command, commit SHA and actual result.
