## Outcome and scope
Resolve exact slug+version+digest and explicit targetSiteId. Authorize source access and target independently. Build schema/relations/seed plan, resource counts, diff, fingerprint, expiry and prerequisite errors. v1 create-only: unrelated collections allowed, collisions rejected unless owned by the identical completed installation. Namespace mapping rewrites every reference. Never silently merge or replace existing data.


## Implementation work breakdown
- [ ] BT03-W1: Implement exact template identity resolution and site-bound planner with stored immutable revision snapshot.
- [ ] BT03-W2: Compute namespace mapping, dependency graph, conflict inventory and target schema fingerprint; persist expiring plan metadata only.
- [ ] BT03-W3: Check runtime/permissions/limits before emitting an actionable plan; return stable errors and component/seed counts.

## Expected code touchpoints
new planner and plan contract/persistence; ConfigImportService dry-run reuse. These are planning boundaries, not exclusive file grants; coordinate shared changes and preserve unrelated work.

## Detailed acceptance criteria
### BT03-AC01 — Explicit destination

- [ ] Missing targetSiteId and mismatch with request site context fail; site A schema/content is unchanged when a valid plan targets B.
- Verification/evidence: Route integration; attach test name, exact command, commit SHA and actual result.

### BT03-AC02 — Dry-run isolation

- [ ] Compare target schema/content before/after plan; unchanged. Only plan/audit metadata may be persisted and is site scoped.
- Verification/evidence: DB snapshot assertions; attach test name, exact command, commit SHA and actual result.

### BT03-AC03 — Conflict policy

- [ ] Existing unrelated collection is preserved; same-name unowned collection produces NAME_CONFLICT even if schema matches; no implicit merge.
- Verification/evidence: Planner fixtures; attach test name, exact command, commit SHA and actual result.

### BT03-AC04 — Reference rewrite

- [ ] Namespace wordpress->blog rewrites every collection/field/relation/seed collection reference; ordinary text containing wordpress is unchanged.
- Verification/evidence: Unit graph tests; attach test name, exact command, commit SHA and actual result.

### BT03-AC05 — Pinned identity

- [ ] Ambiguous display name fails; exact catalog+slug+version pins digest. Source draft edits after planning do not alter plan.
- Verification/evidence: Service tests; attach test name, exact command, commit SHA and actual result.

### BT03-AC06 — Stale and incompatible

- [ ] After schema fingerprint changes, expiry passes, or runtime lacks transactional storage support, plan/apply is rejected before target mutation.
- Verification/evidence: Clock/runtime/DB tests; attach test name, exact command, commit SHA and actual result.
