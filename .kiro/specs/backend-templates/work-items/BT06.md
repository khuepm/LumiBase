## Outcome and scope
Register template_list/get/validate/create/capture/publish/plan/instantiate plus installation_get using existing MCP registry and AISecureHarness. Tool names are proposed; align naming conventions on implementation. Exact shared schemas, capability filtering and runtime permission recheck. Schema writes require HITL bound to target site, template digest, plan fingerprint and seed choice; approval resumes the recorded action once. Metadata is untrusted text, never instructions.


## Implementation work breakdown
- [ ] BT06-W1: Register all authoring/discovery/planning/installation tools and exact shared input/output schemas in existing registry.
- [ ] BT06-W2: Wire capability filtering plus call-time authorization, governed schema approval and single-use resume.
- [ ] BT06-W3: Add recorded MCP sessions covering create->publish->plan->instantiate and independent REST parity.

## Expected code touchpoints
apps/cms/src/services/mcp-service.ts, routes/mcp.ts, packages/ai-skills registry and harness integration. These are planning boundaries, not exclusive file grants; coordinate shared changes and preserve unrelated work.

## Detailed acceptance criteria
### BT06-AC01 — Discoverability

- [ ] Authorized tools/list contains template list/get/validate/create/capture/publish/plan/instantiate/status with exact schemas; insufficient capabilities hide or deny tools consistently.
- Verification/evidence: Golden/schema test; attach test name, exact command, commit SHA and actual result.

### BT06-AC02 — Author via MCP

- [ ] Call create with valid JSON, validate, edit through supported authoring path and publish; get returns same immutable digest and no backend was installed.
- Verification/evidence: Recorded MCP session; attach test name, exact command, commit SHA and actual result.

### BT06-AC03 — Agent install

- [ ] Resolve wordpress-alike 1.0.0, plan for B without seed, instantiate -> pending approval; authorized approval resumes exact plan and returns completed installation with zero content rows.
- Verification/evidence: Real DB MCP session; attach test name, exact command, commit SHA and actual result.

### BT06-AC04 — Bound approval

- [ ] Modify target site, version, digest, seed choice or namespace after approval; reject each tampering case and require new plan/approval.
- Verification/evidence: Security matrix; attach test name, exact command, commit SHA and actual result.

### BT06-AC05 — Denial and replay

- [ ] Deny, expire or revoke caller permission before resume; zero target writes. Repeated approved resume returns same result, no second execution.
- Verification/evidence: Harness integration; attach test name, exact command, commit SHA and actual result.

### BT06-AC06 — Missing site

- [ ] Natural request has no destination; tool returns missing-input error rather than silently using a default site; agent-facing guidance asks for destination.
- Verification/evidence: Recorded contract case; attach test name, exact command, commit SHA and actual result.

### BT06-AC07 — Parity and injection

- [ ] REST/MCP equivalent input yields equivalent normalized result/error; template description containing instructions cannot change capabilities, target or seed choice.
- Verification/evidence: Transport + malicious metadata tests; attach test name, exact command, commit SHA and actual result.
